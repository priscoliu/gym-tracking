## Open Gaps

### GAP-001 — Client coverage: dim_client vs fact_transaction

| Field | Detail |
|---|---|
| **Severity** | High |
| **Status** | Open |
| **Affected measures** | `Global Client Count`, `Addressable Client Count`, all LOB bucket measures, `Penetration Rate` |

**Description:**
Not all clients in `gold_salesops_dim_client` (Silver registry) have rows in `gold_salesops_fact_transaction`. Clients with no transactions are invisible to all fact-based measures.

**Impact:**
- `Global Client Count` undercounts the true client universe
- LOB bucket distributions and penetration rate only reflect transacting clients
- Penetration Rate denominator may be understated

**Query results (2026-04-27):**

| Metric | Count |
| --- | --- |
| Total clients in `dim_client` | 625,364 |
| Distinct clients in `fact_transaction` | 444,034 |
| Missing from fact | 181,943 |
| Coverage | 71.0% |

181,943 clients (29% of the registry) have no transaction records.

**Questions to resolve:**
- Are missing clients a pipeline gap, a source system filter, or genuinely no transactions?
- Should the client universe be defined from `dim_client` (full registry) or `fact_transaction` (transacting only)?
- Is there a date range causing the gap?

**Interim handling:**
All measures currently count from `fact_transaction`. Results reflect transacting clients only — needs caveat on dashboard.
